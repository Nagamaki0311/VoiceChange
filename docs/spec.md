# VoiceChange 仕様書

Windows向けリアルタイムボイスチェンジャー（単一の.exe）。入力デバイスの音声を加工し、VB-CABLE等の出力デバイスへ渡す。ユーザーの原指示を元に、実装上の問題点を調整した版を本書とする。原指示から変えた点は「原指示からの調整」節に理由とともにまとめ、判断の経緯は docs/decisions.md に記録する。

## アーキテクチャ

```
[入力デバイス] --入力コールバック(入力デバイスのスレッド)--> モノラル化 --> SPSCリングバッファ
                                                                           |
[出力デバイス] <--出力コールバック(出力デバイスのスレッド)-- DSPチェーン <-- 可変レートリサンプラ
```

- 入力と出力は別々の`AudioIODevice`として開き、それぞれ独立したコールバックスレッドで動かす。
- 入力コールバックは全チャンネルを平均してモノラル化し、リングバッファ（`juce::AbstractFifo`、容量は入力レートで1秒）へ書くだけにする。
- 出力コールバックはリングバッファから可変レートリサンプラ（`juce::LagrangeInterpolator`）で出力レートへ変換しながら読み、DSPチェーンを通し、出力デバイスの全チャンネルへ複製する。DSPは出力デバイスのサンプルレートで動く。
- 仮想オーディオデバイスは作らない。出力先はVB-CABLE（「CABLE Input」）を想定する。入力元はSteelSeries Sonar等の仮想入力デバイスも区別なく選べる。

### デバイスタイプ

- Windowsでは「Windows Audio (Low Latency Mode)」（`WASAPIDeviceMode::sharedLowLatency`）で開き、`open()`が失敗したデバイスは「Windows Audio」（`WASAPIDeviceMode::shared`）で開き直す。入力と出力は個別にフォールバックする。排他モードは使わない。
- 低遅延モードではデバイスのミックスフォーマットのサンプルレートでしか開けない（JUCE実装はこのモードでOS側のレート変換を無効にしている）ため、各デバイスは既定サンプルレートで開く。レート差はアプリ側のリサンプラで吸収する。
- 低遅延モードのバッファサイズは、デバイスが提示する候補のうち最小のものを使う。
- Linux（開発用）ではJUCEの既定デバイスタイプを使う。Windows固有の処理は`#if JUCE_WINDOWS`で囲む。

### クロックずれ補正（リングバッファ）

- 目標充填量 = max(入力ブロック長, 出力ブロック長) + ジッタ余裕。ジッタ余裕の初期値は2msとし、アンダーラン（出力時に必要量が足りない）が起きるたびに2ms増やす（上限20ms）。
- 充填量は出力コールバックの読み出し直後に測り（D-006）、数秒の時定数で平滑化する。平滑化した充填量と目標の差に比例して、リサンプラの速度比を公称比（入力レート/出力レート）から最大±0.1%補正する。
- 起動直後と、アンダーラン発生後は、充填量が目標に達するまで無音を出す（再充填）。無音への切り替えと復帰には短いフェードをかける。
- 充填量が目標の3倍を超えた場合（出力側の停止からの復帰など）は、超過分を捨てて目標まで戻す。遅延の増大を上限で止めるため。
- リングバッファ遅延の表示値は「平滑化した読み出し直後の充填量 + 出力ブロック長/2」を使う。

## 音声処理チェーン

出力コールバック内で、ブロック単位に次の順で処理する。

1. 入力レベルメーター用のピーク値を記録する（処理前の入力）。
2. マイク処理: ノイズ除去 → EQ（後述「マイク処理: ノイズ除去」「マイク処理: EQ」）。それぞれ独自のON/OFFを持ち、全体OFF（バイパス）の対象外とする（D-020）。
3. ピッチ検出（ケロケロ・トークボックス選択時のみ動かす）。
4. ピッチシフター（Signalsmith Stretch、アプリ全体で1インスタンス）。移調量 = 層1ピッチ + プリセットの移調量 + ケロケロの補正量。フォルマントはプリセットの係数を使い、移調によるフォルマント移動は補償する（`setFormantFactor(係数, true)`）。
5. 層2のピッチ以外の効果（エコー / ロボット / トークボックス）。
6. 層1のリバーブ → ゲイン → リミッター。
7. NaN/Infを検査し、あれば無音にしてDSP状態（マイク処理を含む）をリセットし、エラーフラグを立てる。
8. バイパス（全体OFF）時は3〜6の代わりに2の出力をそのまま出す。7の異常値検査はバイパス中も行う（D-010）。バイパス時の処理はマイク処理と±1.0へのクリップのみ（補間のオーバーシュート対策。D-018）。ON/OFFの切り替えは20msでクロスフェードする。バイパスの解除時にリセットするのは3〜6だけで、マイク処理はリセットしない。

原指示の「層2 → 層1」の順序は維持している。ピッチシフターだけは原指示どおり層1と層2の移調量を合算して1回で処理し、その位置をチェーンの先頭に置く。エコーやリバーブの残響が重なった多声の信号よりも単声の信号の方がピッチシフトの品質が良いこと、ロボットのリングモジュレーション周波数（40Hz）が層1のピッチ操作で変わらないこと、ケロケロの補正量を加工前の声から求められることが理由である。

マイク処理は層2・層1の前に置く。ノイズ除去をEQより前に置くのは、EQで持ち上げた帯域の雑音まで増幅してからノイズ除去へ渡さないためである。ピッチ検出とピッチシフターにも雑音を除いた声が渡る。

### マイク処理: ノイズ除去

目的は空調・PCファン・一般的な背後雑音（定常〜準定常）の除去である。打鍵・マウスクリック等のインパクトノイズは可能な範囲で抑え、発話と重なる打鍵の完全除去は目標にしない。

処理の順序（すべてEngine内、出力レートで動く）:

1. フレーミング: RNNoiseは48kHz・480サンプル（10ms）単位で処理する。入力をFIFOにため、480サンプルそろうごとに1フレーム処理し、出力FIFOから一定の遅延で読み出す。フレーミングの遅延はブロック長の組み合わせに依存しない固定値（48kHzで480サンプル）とする。
2. 48kHz以外の出力レート: RNNoiseの前で固定比の`juce::LagrangeInterpolator`により48kHzへ変換し、RNNoiseの後で出力レートへ戻す（D-021）。変換するのはRNNoiseを通る経路だけで、原音側は変換しない。
3. RNNoise: 入力を32768倍して`rnnoise_process_frame`に渡し、出力を1/32768倍する（RNNoiseは16bit整数の値域の浮動小数点を前提とする）。戻り値の発話確率（VAD、0〜1）を5のゲートで使う。
4. 原音との混合: 原音をRNNoise経路と同じ遅延（整数サンプルに丸める）だけ遅らせ、出力 = (1 − d)・RNNoise出力 + d・原音 とする。
5. VAD連動ゲート（無声区間の残留雑音の抑制、D-022）: 開く条件は VAD ≥ 0.6、または原音の短時間RMS（10ms）が原音の雑音床推定より12dB以上大きいこと。閉じる条件は VAD < 0.3 かつ 短時間RMSが雑音床+6dB未満 の状態が200ms（ホールド）続いたこと。ゲインは開くとき5ms、閉じるとき150msで動かす。雑音床推定は短時間RMSの2秒間の最小値とし、上昇は3dB/秒までに制限する。
6. インパクト抑制（D-023）: 検出は原音（ノイズ除去の入力）で行う。速い包絡（|x|、アタック0.1ms・リリース2ms）と遅い包絡（アタック20ms・リリース200ms）の比が閾値Tを超えたら検出とする。検出した音が出力に届く2ms前から減衰を始める（ノイズ除去の遅延を先読みに使う）。減衰はアタック1ms、ホールド15ms（再検出で延長）、リリース10ms。ゲートが開いている間（発話中）は減衰量を半分にし、閾値を6dB上げる（子音・破裂音の頭を削らないため）。減衰は4・5の後の信号に掛ける。

| パラメータ | 範囲 | 初期値 | 実装 |
|---|---|---|---|
| ノイズ除去 ON/OFF | ON / OFF | OFF | ピッチシフターと同じ状態遷移（Resting / Priming / FadingIn / Active / FadingOut、20msのクロスフェード） |
| 背景ノイズ s | 0〜100%（1%刻み） | 70% | s ≤ 50%: d = (1 − 2s)²、ゲートなし（25%で原音−12dB、45%で−40dB）。s > 50%: d = 0、ゲートが閉じたときの減衰量 = 18dB × (2s − 1)。d と減衰量は`SmoothedValue`（50ms）で補間 |
| インパクトノイズ s_i | 0〜100%（1%刻み） | 0% | 0%で検出・減衰を止める。閾値 T = 30 − 18・s_i [dB]、減衰量 = 24・s_i [dB]。減衰量は`SmoothedValue`（50ms） |

- 数値は初期値であり、実録音の比較と聴感で調整してよい。調整した場合は本表を更新する。
- 実装の補足（T-011。上の数値には影響しない、仕様が定めていない部分の実装上の取り決め）:
  - VAD: RNNoiseの戻り値を、そのフレームが出力FIFOへ足したサンプルに対応づける（出力と同じ位置で読む）。実測ではVADは立ち上がりで出力より約1フレーム（10ms）早く上がり、立ち下がりでは出力と同じ位置で下がる。
  - ゲート: 判定は遅延線の出力（原音を出力と同じDだけ遅らせたもの）で行う。短時間パワーは10msの窓で、遅延線が埋まり窓が満ちるまで（D + 10ms）は開いたままにする。雑音床は−90dBFSを下限とする（デジタル無音で床が0になると、以後3dB/秒でしか上がらず開いたままになるため）。ゲインは線形に動き、閉じたときのゲイン（10^(−減衰量/20)）を50msで補間する。s ≤ 50%ではゲインは常に1だが、開閉の状態は常に更新する（インパクト抑制が参照する）。
  - インパクト抑制: 検出は遅延線の「出力より2ms新しい位置」の原音で行う。ゲートが開いているか（閾値+6dB・減衰量の半分）は検出した時点の状態で決め、その減衰量をホールドの間保つ。遅い包絡の下限は−80dBFS（無音の直後の発話や、パイプライン開始直後に比が無限大になって誤検出しないため）。包絡は最初の1サンプルで入力に合わせる。s_i = 0では減衰段のゲインは常に1（ビット一致）。
- 遅延: ノイズ除去の遅延 = フレーミング（48kHzで480サンプル）+ RNNoise固有の遅延 + 変換の遅延（48kHz以外のみ、数サンプル）。RNNoise固有の遅延はT-009の実測で960サンプル（20ms）、48kHzのノイズ除去の遅延は480 + 960 = 1440サンプル（30ms）。48kHz以外では出力FIFOの初期充填（ceil(480×fs/48000) + 4 + 2×ceil(fs/48000)）と変換の遅延を含め、44.1kHzで1333サンプル（30.2ms）、96kHzで2893サンプル（30.1ms）、192kHzで5781サンプル（30.1ms）。報告値と実測値（相互相関）は±1サンプル以内で一致する（T-010のN6）。表示するレイテンシに「除去」として加える。
- ON/OFF: OFF（Resting）ではRNNoiseを呼ばず、バッファに触れない（ビット一致）。ONにした直後は遅延分の入力がそろうまで原音を出し、その後20msで切り替える。切り替えでは遅延分（30ms）の音が重複または欠落する（D-002と同じ帰結。クロスフェードでクリックは防ぐ）。
- 異常値: `NoiseReducer::process`の入力に非有限値があれば、その場で検出する（RNNoiseの出力側では検出がDサンプル遅れるため）。ノイズ除去の出力に現れた非有限値（有限だが巨大な入力でRNNoiseの内部状態が壊れた場合など）は、最終出力の非有限値検査で検出する。異常を検出したら、`rnnoise_init`でRNNoiseの状態を初期化し（確保なし）、FIFO・遅延線・包絡を消去する。

### マイク処理: EQ

- 5バンドのパラメトリックEQとする（SteelSeries Sonarの既定バンド数に合わせる。Sonarは最大10バンド）。バンド数は定数とし、再現するSonarの設定が5バンドを超える場合は増やす。
- 各バンドは有効/無効・タイプ・周波数・ゲイン・Qを持つ。`juce::dsp::IIR::Filter`（2次）を直列に並べる。係数は`IIR::ArrayCoefficients`で計算し、`prepare()`で作った`Coefficients`へ代入する（代入は確保しない。D-024）。

| パラメータ | 範囲 | 初期値（仮） | 実装 |
|---|---|---|---|
| EQ ON/OFF | ON / OFF | OFF | 20msのクロスフェード。OFFのフェード完了後は処理せず、バッファに触れない（ビット一致） |
| 有効/無効（バンドごと） | ON / OFF | 5バンドとも有効 | 20msで素通し（y = x）へクロスフェード |
| タイプ | ピーキング / ローシェルフ / ハイシェルフ / ローカット / ハイカット | 1: ローシェルフ、2〜4: ピーキング、5: ハイシェルフ | 変更時は20msで素通しへ → 係数を切り替えてフィルタ状態をリセット → 20msで戻す |
| 周波数 | 20〜20000Hz（1Hz刻み） | 100 / 250 / 1000 / 3000 / 8000Hz | 実効値は0.45×出力レートで頭打ち。`SmoothedValue`（Multiplicative、50ms） |
| ゲイン | −18〜+18dB（0.1dB刻み） | 0dB | `SmoothedValue`（50ms、dBで補間）。ローカット・ハイカットでは使わない |
| Q | 0.10〜10.00（0.01刻み） | 0.71 | `SmoothedValue`（Multiplicative、50ms） |

- 初期値（仮）は、Sonarの設定（ユーザーから受け取るスクリーンショット）を再現した値にT-015で置き換える。Sonarとフィルタの定義（Qの意味、カットの傾き）が違う場合は、周波数特性が一致するよう換算する。
- 低域カット: 既定ではどのバンドもローカットにしない。声の基本周波数（低い声で70〜120Hz）を削らないため。ローカットを使う場合、70Hzでの減衰を0.5dB以内に収めるには周波数を40Hz以下にする（Q = 0.71、12dB/oct）。
- 補間中は32サンプルごとに係数を再計算する。再計算の周期はサンプル数で数え、ブロックの区切りに依存させない（分割処理のビット一致のため）。

### ピッチシフターの休止

- 合計移調量が0かつフォルマント係数が1のとき（ノーマル・エコー・ロボット・トークボックスで層1ピッチが0のとき）はピッチシフターを通さない。CPU使用率の要件（ノーマル時1%未満）を満たすため。Signalsmith Stretchは移調0でもSTFTの計算を行い、1コアの約1.5%を使うことを実測で確認している。
- 休止中はピッチシフターの遅延（ブロック長分）がなくなり、遅延が小さくなる。休止から稼働への切り替えでは`reset()`後にシフターへ入力を送り始め、シフターの遅延分の出力が揃ってから20msでクロスフェードする。稼働から休止へは20msでクロスフェードした後に止める。
- 表示するレイテンシは、その時点の経路（シフター稼働中か否か）に応じた値とする。

### ブロック長の決定

Signalsmith Stretchの遅延（inputLatency + outputLatency）はブロック長にほぼ等しい。ブロック長20〜40msでは移調後の音程が1〜5%ずれ、120msで0.6%以内に収まることを実測した（D-013）。

- ブロック長は120ms、インターバルは30msに固定する（D-014）。
- 50msの遅延目標はシフター休止時の経路に適用する。シフター稼働中は約120ms加わる。ノイズ除去ON時の扱いはD-025。

|---|---|---|---|
| ゲイン | -20〜+20dB | 0dB | `SmoothedValue`（Multiplicative、50ms）で補間 |
| ピッチ | -12〜+12半音（1半音刻み） | 0 | ピッチシフターの移調量に加算。フォルマントは保持する |

- 数値は初期値であり、聴感で調整してよい。調整した場合は本表を更新する。
- プリセット切り替え時は、旧効果と新効果を20ms並行して処理しクロスフェードする。移調量・フォルマント係数の変更はシフター内部の重ね合わせでつながる。
- ケロケロ: 平均律（A4 = 440Hz）の最寄りの半音への補正量 = round(m) − m（m = 検出した音高のMIDIノート番号）。無声・無音区間では補正量を直前の値に保つ。
- ロボット: 原指示どおりリングモジュレーションで実装する。リングモジュレーションは金属的な響きを作るが抑揚は残る。抑揚を消す別案（ピッチを一定値へ補正する）は本書の範囲外とし、READMEに記録する。

#### トークボックス（チャンネルボコーダー）

- 20バンド、中心周波数は120Hz〜min(7kHz, 出力レート×0.4)の対数等間隔。各バンドは2次バンドパス（`juce::dsp::IIR`）を2段重ねる。
- 変調信号（ピッチシフター後の声）の各バンドの包絡を全波整流 + 1次ローパス（アタック5ms、リリース20ms）で抽出し、キャリアの同じバンドの出力に掛けて合算する。
- キャリア: 検出した基本周波数 × 2^(層1ピッチ/12) の鋸波（PolyBLEPで折り返し雑音を抑える）。有声度に応じて白色雑音と混ぜる（無声区間は雑音のみ）。無声区間の鋸波の周波数は直前の値を保つ。
- 出力音量が入力と大きく変わらないよう、固定の補正ゲインをかける。**補正ゲイン = 0.904（約-0.9dB）**。母音3種（/a/・/i/・/u/相当）×f0 3種（100/150/250Hz）・-20dBFS付近の合成母音でTalkboxの出力RMSを測り、その中央値+0.88dBを打ち消す値（tests/EffectsTests.cppのX3a。補正後の出力は入力比-1.8〜+2.1dB、Engine経由のX3で-1.8〜+2.9dB）。
- 実装上の調整（テストで決定）: バンドパスのQは変調側3.0、キャリア側1.5（2段）。キャリア側の各バンド出力は、自身の包絡（変調側と同じ全波整流+アタック5ms/リリース20ms）で割って正規化してから変調側の包絡を掛ける。鋸波の-6dB/oct傾斜とf0による倍音数の違い、隣接バンドの境目に倍音が来たときの位相打ち消し（f0=250Hzの/u/で入力比-12dB）を抑え、母音・f0による音量差を約15dBから約4dBに縮めるため。

### ピッチ検出モジュール（ケロケロ・トークボックス共通）

- YIN法。入力を約12kHzへ間引いてから計算する（間引き係数 = round(出力レート/12000)、前段にアンチエイリアスのローパス）。
- 検出範囲70〜1000Hz、積分窓約21ms、ホップ約5ms。累積平均正規化差分関数の閾値0.15と、放物線補間による小数周期推定を使う。
- 出力: 基本周波数（Hz）と有声度（0〜1）。RMSが閾値未満なら無声とする。
- 必要なバッファはすべて`prepare()`で確保する。

## 音声スレッドの制約

- 音声コールバック内でメモリ確保・解放、ロック、ファイルI/O、ログ出力をしない。バッファはすべてデバイスを開く前の`prepare()`で確保する（Signalsmith Stretchの`configure()`もここで呼ぶ。`process()`は`configure()`で確保した容量の範囲で動く）。
- UIと音声スレッド間のパラメータはすべて`std::atomic`で渡す。メーター値・統計値も同様。
- 音声コールバックは処理全体を`try/catch(...)`で囲み、例外時は無音を出してエラーフラグを立てる。
- 出力コールバックの要求サンプル数が`prepare()`時の最大値を超えた場合は、最大値ごとに分割して処理する。
- RNNoise（C）は`rnnoise_create`でのみ`malloc`する。`rnnoise_process_frame`はスタック配列だけを使う（ソースで確認）。`rnnoise_create`は`prepare()`、`rnnoise_destroy`はデストラクタ（いずれもメッセージスレッド）でのみ呼ぶ。音声スレッドでのリセットは`rnnoise_init`で行う。
- EQの係数は`IIR::ArrayCoefficients`（`std::array`を返す）で計算し、`prepare()`で作成済みの`Coefficients`へ代入する。`IIR::Coefficients::make*`は`prepare()`でのみ呼ぶ。

## 機能要件

### デバイス選択

- 入力・出力デバイスをドロップダウンで選ぶ。Windowsが認識する全デバイスを物理・仮想の区別なく列挙する。
- 各デバイスのモード（低遅延 / 通常）を表示する。
- 選択中のデバイスが取り外された・無効化された場合はエラーを表示し、クラッシュさせない。検出手段は3つ: デバイス一覧の変更通知、`audioDeviceError`、音声コールバックの停止を監視するウォッチドッグ（2秒間コールバックが進まなければ異常とみなす）。
- デバイスが一覧に戻ったら自動で開き直す。一覧変更通知が来ない場合に備え、異常状態の間は2秒ごとに再接続を試みる。片方だけの異常でも両方を閉じ、両方揃ってから開き直す。起動時に保存済みのデバイスが見つからない場合は既定デバイスへ切り替えず、エラーを表示して再試行を続ける（D-009）。
- 多重起動は禁止する（D-009）。
- 初回起動時の既定値: 入力はシステム既定の入力デバイス、出力は「CABLE Input」を含むデバイス（なければシステム既定の出力）。

### 設定の保存

- `juce::PropertiesFile`で`%APPDATA%\VoiceChange\VoiceChange.settings`に保存する。項目: 入力デバイス名、出力デバイス名、ゲイン、ピッチ、リバーブ、プリセット、ON/OFF、初回格納通知の済みフラグ、ノイズ除去のON/OFF・背景ノイズ・インパクトノイズ、EQのON/OFFと各バンドの有効/無効・タイプ・周波数・ゲイン・Q。
- 値の変更から1秒後にまとめて保存し、終了時にも保存する。
- 読み込んだ値は範囲外なら範囲内へ丸め、非有限値は初期値にし、不明なプリセット名はノーマル、不明なEQのタイプ名はピーキングにする。

### VB-CABLE検出

- 起動時に出力デバイス名に「CABLE Input」を含むものがあるか確認し、無ければ未インストールである旨と公式サイト（https://vb-audio.com/Cable/）を非モーダルのダイアログで表示する。ダイアログにはサイトを開くボタンを置く。インストーラは同梱しない。

### システムトレイ

- 閉じるボタンでトレイに格納する。初回の格納時のみ、トレイに格納した旨の通知を出す。
- トレイアイコンの左クリックでウィンドウを表示する。右クリックメニュー: ウィンドウを表示 / ON・OFF切り替え / 終了。
- トレイアイコン画像はコード内で描画する（画像ファイルを同梱しない）。

### 計測とログ

- UIの下部に常時表示: 合計レイテンシ（ms）、内訳（デバイス入出力 / リングバッファ / ノイズ除去 / ピッチシフター）、CPU使用率、各デバイスのモード。
- CPU使用率の定義: 出力コールバック内の処理時間 ÷ そのコールバックが担当する音声の長さ（1コアあたりの割合）。原指示の「ノーマル時1%未満、重い効果でも5%以下」はこの定義で判定する。ノイズ除去・EQをONにしたときの要件は「パフォーマンス要件」節による。
- 60秒ごとに`%APPDATA%\VoiceChange\VoiceChange.log`へ統計を追記する（メッセージスレッドから）。項目: 経過時間、レイテンシ、リングバッファ充填量、アンダーラン/オーバーラン回数、速度比補正量、CPU使用率、プロセスのメモリ使用量（Windowsでは`GetProcessMemoryInfo`）、ノイズ除去とEQのON/OFF（CPU要件の判定条件を区別するため）。1時間連続動作テストの判定材料にする。ログは起動時に1MBを超えていれば作り直す。

## UI

- 固定サイズのウィンドウ。上から順に: 入力デバイス選択（右にマイク処理ボタン）→ 出力デバイス選択 → 入力レベルメーター → 音響卓（ゲイン / ピッチ / リバーブのスライダー）→ プリセットボタン群（択一、8個）→ 全体ON/OFFトグル → 状態表示（レイテンシ・CPU・エラー）。ノイズ除去とEQの設定は、マイク処理ボタンで開く別ウィンドウ（マイク処理ウィンドウ）で行う。
- 表示言語は日本語。
- レベルメーターとステータス表示は30fpsのタイマーで更新し、ウィンドウが非表示の間はタイマーを止める。
- 詳細なデザイン（サイズ・配色・配置）は docs/design.md に記載する。

## パフォーマンス要件

- 目標レイテンシ: ピッチシフター休止時は50ms以下、稼働時はそれに約120msを加えた値。ノイズ除去ON時は、さらにノイズ除去の遅延（固定。30ms = 1440サンプル@48kHz、T-009・T-010の実測）を加えた値（本アプリ単体。Sonar等の前段処理は含まない。D-014、D-025）。50ms目標の判定（W2）はデバイス入出力 + リングバッファで行う。レイテンシ = デバイス入出力遅延（JUCEが報告するストリーム遅延 + バッファ長）+ リングバッファ遅延（実測）+ ノイズ除去遅延（ON時のみ）+ ピッチシフター遅延（稼働時のみ、inputLatency + outputLatency）。
- CPU使用率: 上記定義で、ノイズ除去・EQがOFFのときノーマル時1%未満、トークボックス等でも5%以下。ノイズ除去・EQをONにしたときの増分は3%以下とする（目標値。T-009・T-011・T-012の実測値を見て確定する。D-025）。
- ウィンドウ非表示・非フォーカス時も処理を継続する。

## 検証方針

| 対象 | 方法 | 実行環境 |
|---|---|---|
| リングバッファ・クロックずれ補正 | 入出力のレート差（±100ppm、44.1kHz→48kHz等）とブロック長の違いを模擬し、音声時間で1時間分をオフラインで回す。充填量が有界、初期充填後のアンダーラン0、遅延が増えないことを確認 | Linux / Windows CI |
| ピッチシフター | 正弦波・合成母音の移調量とフォルマント移動を測定。休止⇔稼働の切り替えでクリックがないこと | 同上 |
| ピッチ検出 | 既知の周波数の正弦波・鋸波・合成母音で誤差を測定（目標: 有声音で±1%以内） | 同上 |
| 各プリセット | NaN/Infが出ないこと、出力が0dBFSを超えないこと、切り替え時に隣接サンプル差が閾値以下（クリックなし） | 同上 |
| 異常値 | NaNを注入し、無音化・エラーフラグ・復帰を確認 | 同上 |
| ノイズ除去 | 合成母音（ビブラート・音節の抑揚付き、f0 85〜250Hz）に合成の定常雑音・クリックを重ね、SNR改善量・無声区間の残留雑音・発話区間の歪み・低い声の減衰・クリック除去量・遅延を測定。NaN注入、切り替えのクリック、分割処理の一致、アロケーション0回 | Linux / Windows CI |
| EQ | インパルス応答のFFTで、各タイプの周波数特性が解析式と0.1dB以内で一致すること。パラメータ変更・タイプ切り替えでクリックがなく、極端な値でも発散しないこと | 同上 |
| マイク処理OFF | ノイズ除去・EQがOFFのとき、バッファがビット一致 | 同上 |
| 実録音での比較 | Sonarを通さない生音声とSonar適用後の音声を同時に録音し、生音声に本アプリの処理をかけて、無声区間の残留雑音・発話と残留雑音の比・長時間平均スペクトルを比較する（手順はREADME）。聴感評価はユーザーが行う | Linux（オフライン処理）+ ユーザー |
| CPU | 各プリセットの処理時間 ÷ 音声時間を測定 | 同上（参考値） |
| .exeのビルド | MSVC `/MT`、依存DLLがないこと（`dumpbin /dependents`でVC++ランタイムDLLが含まれない） | Windows CI |
| 実機動作・聴感・1時間連続動作 | ユーザーが実機で行う。手順はREADMEに記載し、ログで判定する | Windows実機 |

## 原指示からの調整

| 項目 | 原指示 | 調整後 | 理由 |
|---|---|---|---|
| デバイスの開き方 | 指定なし（JUCEのデバイス管理） | 入力・出力を別々の`AudioIODevice`として開く | JUCEの一体型WASAPIデバイスは入出力を1スレッドで回し共通サンプルレートを要求するため、別クロックのずれ補正とレート差の吸収という要件と両立しない |
| ピッチシフターの位置 | 層2→層1の順 | チェーン先頭（合算は原指示どおり） | 単声の信号の方が品質が良い、リングモジュレーション周波数が変わらない、ケロケロの補正を加工前の声から求められる |
| ピッチシフターの休止 | 記載なし | 移調0・フォルマント1のとき休止 | CPU要件と遅延の短縮 |
| ブロック長 | 50msに収まる最も長い設定 | 120ms固定。50ms目標はシフター休止時に適用（D-014） | 50ms以内に収まるブロック長では移調後の音程が1〜5%ずれる。ユーザー判断で音程の正確さを優先 |
| リングバッファ目標 | 記載なし | ブロック長 + 自動調整するジッタ余裕 | 遅延を最小限にしつつ、環境ごとのスケジューリングの揺れに追従する |
| CPU使用率 | 定義なし | 1コアあたりの処理時間比 | 判定可能にするため |
| 1時間連続動作 | 確認する | 統計ログを出し、ロジックはオフライン模擬で検証、実機はユーザーが実施 | 開発環境がLinuxで、実機のオーディオデバイスがないため |
| 全体OFFの対象 | エフェクト全体（原音をそのまま出す） | 層1・層2のみ。マイク処理は独自のON/OFFを持つ（D-020） | Sonarを経由していたときも、本アプリをOFFにするとSonarの処理は残っていた。同じ使い勝手を保つ |
| 無声区間の残留雑音の抑制 | スペクトルゲート | RNNoiseの発話確率に連動する広帯域ゲート（D-022） | 帯域ごとの抑制はRNNoise自体が行う。追加依存やFFT処理のない最小構成から始め、実録音で不足が分かった場合にだけスペクトル処理を検討する |
| ノイズ除去の遅延 | 50ms目標 | ノイズ除去分は目標の外で加算し、内訳に表示する（D-025） | 480サンプル単位の処理とRNNoiseの先読みで固定の遅延が生じる。Sonarを経路から外すことでSonar自身の遅延はなくなる |
