# デザイン品質の判断基準

表面的な要素の禁止リストではなく、制作物ごとの文脈からデザインを決定するための考え方を示す。

## 判断の出発点

デザインは次の関係から導く。**種類 → 目的 → ユーザー → 利用環境 → コンテンツ → 操作方法 → 情報密度 → ブランド・世界観 → 視覚表現 → モーション**

制作物の種類によって優先順位が変わる。判断の出発点として使う（実際の制作物に応じて調整する）。

| 種類 | 優先すべき要素の例 |
|---|---|
| スマホアプリ | タッチ操作、片手操作、操作速度、情報階層、画面遷移 |
| 業務ツール | 情報密度、視認性、操作効率、状態表示、エラー防止 |
| Webサイト・LP | ブランド、コンテンツ、視線誘導、スクロール体験 |
| ゲーム | 世界観、没入感、操作フィードバック、演出、モーション |
| プレゼンテーション | 情報階層、視認性、編集効率、発表時の見せ方 |
| ダッシュボード・データ可視化 | 情報密度、比較のしやすさ、更新頻度への耐性 |
| EC | 商品の見やすさ、購買導線、信頼感 |

## 「AIっぽい」要素の扱い

以下は理由なく既定として使わない。ただし絶対禁止ではない。制作物の目的・ブランド・UX上の明確な理由があれば使ってよい。判断基準は「要素の禁止」ではなく「理由のあるデザイン決定」である。

- 紫色・青紫色のグラデーション
- 大量のカード、すべてをカード化する構成
- 過剰な角丸・過剰なドロップシャドウ
- グラスモーフィズム、意味のないグロー
- 巨大なCTA、SaaSテンプレート風レイアウト、汎用的なダッシュボード
- 画一的なシステムフォント、意味のないアイコン
- 装飾目的だけのアニメーション

使う場合は、理由（ブランド上の意図、ユーザー体験上の必然性等）を設計仕様に残す。

## 独創性

タイポグラフィ、フォントの組み合わせ、カラーパレット、グリッド、非対称レイアウト、余白、視覚的な階層、テクスチャ、レイヤー、奥行き、イラスト、アイコン、インタラクション、トランジション、スクロールアニメーション、状態変化、マイクロインタラクションなどを、制作物固有の特徴から検討する。奇抜さを目的にせず、独創性と使いやすさを両立する。

## モーション・アニメーション

アニメーションには目的を持たせる。「動かせるものは全部動かす」実装はしない。

- 目的の例: 操作フィードバック、状態変化、画面遷移、情報の優先順位、視線誘導、空間関係の説明、世界観、没入感、操作の楽しさ
- 量・速度・イージング・タイミングは制作物の性質で判断する。例: 業務ツールは操作効率を阻害しない範囲に抑える、ゲームは必要に応じてより積極的な演出を使う

## UI状態の設計

ローディング・エラー・空状態・フォーカス状態・タッチ操作時の状態を、通常状態と同じ水準で設計する。実装時の後付けにしない。

## 既存デザインシステムとの整合

対象リポジトリに既存のデザインシステム・再利用可能なUIコンポーネントがある場合、新しい制作物の既定の選択より優先する。配色・タイポグラフィ・余白のトークンは、対象リポジトリのCLAUDE.mdまたはテーマファイルに記録し、Claude Codeの標準機能（Artifacts生成時の組み込みdesign skill等）がそれを参照できるようにする。project001自体はテンプレートでありUI実装を持たないため、固有のデザイントークンは持たない。個別アプリ側で記録する。
